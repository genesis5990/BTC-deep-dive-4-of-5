Welcome to Class 4

So far your team has learned what Bitcoin is, how keys and addresses work, and — last class — how the UTXO model actually moves value: every transaction consumes whole coins (UTXOs) and creates new ones, like breaking and re-minting bills.

Today we put that knowledge to work. You will learn how investigators follow value across the blockchain even when nobody on the chain uses a name, using:

  • Tracing heuristics — the standard assumptions that make clustering possible
  • A hands-on tracing lab — step-by-step tracing of a fabricated transaction chain, with worksheets you can reproduce live
  • OP_RETURN — the provably-unspendable output type that carries data, and what that data can tell an investigator
  • Visual analysis workflow — a tool-agnostic method for turning raw transaction data into an evidentiary graph
  • A capstone case study — a ransom payment followed from victim to cash-out

⚠️ Ground rules for this class

  • All data in this course is fabricated. TXIDs, addresses, amounts, and timestamps are invented for training. Treat every dataset the same way in real casework: record source, date, and method of collection.
  • Heuristics are assumptions, not proof. Every clustering technique you will use today can break (coinjoin, payjoin, Lightning, exchange batching). Your report must say which heuristic was used and why it was considered reliable for that case.
  • No provider names. Any reputable block explorer and any graphing/visualization tool works. We teach method, not brands. Budget note: excellent free explorers exist; commercial-grade graphing tooling ranges from free/open-source to enterprise subscriptions — evaluate with your procurement office.

Learning objectives

By the end of this hour, each participant will be able to:
  1. Explain why the UTXO model makes tracing possible (and what its limits are).
  2. Apply the three core heuristics: common-input ownership, change detection, and address reuse.
  3. Walk a fabricated multi-hop chain from a victim payment to a cash-out point and document each hop.
  4. Recognize OP_RETURN outputs, decode what they typically carry, and describe their investigative value and limits.
  5. Produce a clean, defensible visual graph of a traced flow using any explorer + graphing tool.
