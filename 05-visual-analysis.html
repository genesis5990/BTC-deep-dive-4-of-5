Visual Analysis: From Raw Data to Evidentiary Graph

Any explorer plus any graphing tool (free, open-source, or commercial) can produce court-ready visuals — the method matters more than the software. Brand-agnostic rule of thumb: explorer for facts, graph tool for structure, your notebook for conclusions.

The 7-step visual tracing workflow

1 · Scope. Define the question: "trace ransom payment T1 to cash-out" — not "map everything the suspect ever touched". Unscoped graphs drown analysts.
2 · Anchor & preserve. Record the starting txid (full 64 hex), block height, timestamp, and a screenshot before expanding anything. Then hash your export files (box below) and note tool name + version. This is your chain of custody.
3 · Expand one hop at a time. Add only the addresses you can justify (heuristics from segment 2). After every expansion ask: does this node carry my value forward? If not, park it.
4 · Color by role, not by address. One color per role: victim (orange), suspect cluster (blue), change spine (highlighted), service/cash-out (green), data outputs (grey). Consistent colors across every exhibit.
5 · Follow the change spine first. The single highest-value habit: trace change outputs forward before fanning out. Change is the suspect's own footprint; the peel chain will lead you to the cash-out faster than any spray of outputs.
6 · Annotate on the graph. Put txids, timestamps, and amounts on edges. Mark heuristic strength per node (fact / strong / inference). If a colleague (or a defense expert) can't reproduce your reading of the graph from the graph alone, it isn't done.
7 · Export & report. Export the graph image plus the underlying table (same worksheet as the lab). Statement-ready sentence pattern: "On 03-03 at 04:12 UTC, UTXO …p2 was spent in tx …e908, transferring 1.2495 BTC to address …ex, consistent with a service deposit address receiving from 40+ sources."

📦 Step 2 explained: "Hash your export files" — what that actually means

A hash (e.g., SHA-256) is a digital fingerprint of a file. Run any file through a hash function and you get a unique string of characters. Change even one byte — a single digit in a TXID — and the fingerprint comes out completely different. Hashing your exports means: lock the exact bytes you relied on, provably, the moment you collect them.

The 30-second habit, concretely:

# Windows (built-in, no install):
certutil -hashfile T1-T7_export.csv SHA256

# macOS / Linux (built-in):
shasum -a 256 T1-T7_export.csv
# (or) sha256sum T1-T7_export.csv

You will get something like 3b7a9f…e4c1 T1-T7_export.csv. Write that string in your worksheet next to the file name, the collection date/time (UTC), the tool + version, and your initials. Later, anyone — a supervisor, a prosecutor, a defense expert — can re-run the same command on the file and confirm it produces the identical fingerprint.

What this buys you in court:

  • Integrity proof — the export has not been altered since collection, because any edit would change the fingerprint. This defeats "the analyst edited the spreadsheet" challenges.
  • Chain of custody — combined with your date/time/tool/version notes, the hash shows what was collected, when, and how.
Two things hashing does NOT prove: (1) accuracy — a hash proves the file is unchanged, not that the explorer showed true data (that's why you record tool + version, so the collection method itself can be examined); and (2) who made it — anyone with the file can recompute its hash. Integrity ≠ authenticity of source.

Reading graphs like an analyst

Geometry cheatsheet
  • Long thin chain → peel chain; follow the spine
  • Starburst in → consolidation sweep (pre-cash-out)
  • Starburst out → payouts or mixer split
  • Equal-size ring → CoinJoin; don't cluster inputs
  • 0-value grey nodes → OP_RETURN; decode, don't trace
Common failure modes
  • Expanding 3 hops in every direction at once → unreadable hairball
  • Treating every output as suspect-controlled (miss the service deposit)
  • Clustering CoinJoin inputs → false attribution, case damage
  • No timestamps on edges → can't show sequencing in court
  • Graph with no source table and no hashes → not reproducible
Court-ready standard: your visual is an exhibit; the worksheet table is the evidence; the hash log is the lock. The picture persuades, the table proves, the fingerprint guarantees nothing changed. Always serve all three.
